# DeepSeek API 参数建议

## 📊 模型选择建议

### 推荐模型：`deepseek-chat`

**理由**：
- ✅ 性价比高，适合长文本生成
- ✅ 中文理解能力强
- ✅ 支持长上下文（32K tokens）
- ✅ 适合生成结构化的健康管理内容

### 备选模型（如果可用）：
- `deepseek-chat-v2` - 如果可用，性能更好
- `deepseek-chat-v3` - 如果可用，最新版本

**不推荐**：
- `deepseek-coder` - 专为代码生成，不适合内容生成

---

## 🌡️ Temperature（温度）参数建议

### 评估报告节点
**推荐值：`0.7`**

**理由**：
- 需要准确性和科学性，不能太随机
- 需要一定的创造性来提供个性化建议
- 0.7 平衡了准确性和创造性

**当前设置**：✅ 0.7（已优化）

---

### 饮食计划节点
**推荐值：`0.8`**

**理由**：
- 需要更多创造性来提供多样化的食物选择
- 需要灵活性来适应不同用户条件
- 0.8 提供足够的多样性，同时保持合理性

**当前设置**：✅ 0.8（已优化）

---

### 训练计划节点
**推荐值：`0.8`**

**理由**：
- 需要创造性来设计多样化的训练方案
- 需要灵活性来适应不同设施条件
- 0.8 提供足够的多样性，同时保持安全性

**当前设置**：✅ 0.8（已优化）

---

## 📏 Max Tokens（最大生成长度）参数建议

### 评估报告节点
**推荐值：`4000`**

**理由**：
- 需要生成详细的8个部分内容
- 需要包含常见问题解答、应急方案等
- 4000 tokens 约等于 3000-3500 中文字符，足够详细

**当前设置**：✅ 4000（已优化）

**如果内容经常被截断**：可以增加到 `5000`

---

### 饮食计划节点
**推荐值：`6000`**

**理由**：
- 需要生成7天的详细饮食计划
- 每天需要包含早、午、晚、加餐
- 需要包含替换选项、营养分析、常见问题等
- 6000 tokens 约等于 4500-5000 中文字符

**当前设置**：✅ 6000（已优化）

**如果内容经常被截断**：可以增加到 `8000`

---

### 训练计划节点
**推荐值：`8000`**

**理由**：
- 需要生成完整的N周训练计划（N可能是4-52周）
- 每周需要包含多个训练日的详细计划
- 每个动作需要详细的说明和注意事项
- 需要包含常见问题、应急方案、安全提示等
- 8000 tokens 约等于 6000-7000 中文字符

**当前设置**：⚠️ 6000（建议增加到8000）

**如果周数较多（>12周）**：可以增加到 `10000` 或 `12000`

## 🔧 参数调整建议

### 如果内容太短或不够详细
- **增加 max_tokens**：按需增加 1000-2000
- **保持 temperature 不变**：避免内容变得不准确

### 如果内容太随机或不准确
- **降低 temperature**：从 0.8 降到 0.7 或 0.6
- **保持 max_tokens 不变**

### 如果内容太死板或缺乏创造性
- **提高 temperature**：从 0.7 提高到 0.8
- **保持 max_tokens 不变**

### 如果内容经常被截断
- **增加 max_tokens**：按需增加
- **检查提示词长度**：确保提示词不会占用太多 tokens

---

## 💡 最佳实践建议

### 1. 提示词优化
- 保持提示词清晰、结构化
- 使用明确的格式要求
- 避免过于冗长的提示词（会占用 tokens）

### 2. 内容质量控制
- 在 System Prompt 中明确要求输出质量
- 要求使用 Markdown 格式
- 要求包含具体的数值和依据

### 3. 成本优化
- 根据实际需要调整 max_tokens
- 不要设置过大的 max_tokens（会增加成本）
- 如果内容经常被截断，再逐步增加

### 4. 错误处理
- 如果生成的内容不完整，可以增加 max_tokens 后重试
- 如果生成的内容质量不好，可以降低 temperature 后重试

## 📝 注意事项

1. **成本考虑**：max_tokens 越大，成本越高，建议根据实际需要调整
2. **响应时间**：max_tokens 越大，生成时间可能越长
3. **内容质量**：temperature 过高可能导致内容不准确，过低可能导致内容死板
4. **测试验证**：建议先用推荐值测试，根据实际效果调整

---

## 🔍 如何判断参数是否合适

### Temperature 判断
- **太随机/不准确**：降低 temperature
- **太死板/缺乏创造性**：提高 temperature
- **刚好平衡**：保持当前值

### Max Tokens 判断
- **内容被截断**：增加 max_tokens
- **内容完整但有多余**：可以适当减少（节省成本）
- **内容刚好完整**：保持当前值
