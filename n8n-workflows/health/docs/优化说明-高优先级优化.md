# 健康管家工作流 - 高优先级优化说明

## 优化概览

本次优化主要针对以下四个高优先级问题：

1. ✅ **提取重复代码为通用函数节点**
2. ✅ **并行执行三个AI调用**
3. ✅ **增强错误处理和重试机制**
4. ✅ **优化数据传递链路**

## 1. 提取重复代码为通用函数节点

### 问题
三个"清理和转换"节点（评估结果、饮食计划、训练计划）包含大量重复的Markdown转HTML代码（约200行），维护成本高。

### 解决方案
创建一个通用的"Markdown转HTML工具函数"节点，其他节点调用该函数。

### 实施步骤

#### 步骤1：创建通用函数节点
新增节点：**"Markdown转HTML工具函数"**

```javascript
// 通用Markdown转HTML转换函数
// 输入：{ rawText: string, profile: object, calculations: object, fieldName: string }
// 输出：{ profile, calculations, assessment: { markdown, html } }

const input = $input.item.json;
const rawText = input.rawText || '';
const fieldName = input.fieldName || 'content';

// 清理转义字符
function cleanEscapeChars(text) {
  if (!text || typeof text !== 'string') return '';
  return text
    .replace(/\\n/g, '\n')
    .replace(/\\"/g, '"')
    .replace(/\\\\/g, '\\')
    .replace(/\\t/g, '\t')
    .replace(/\\r/g, '\r')
    .replace(/\n{3,}/g, '\n\n');
}

// 将 pipe 风格表格转换为 HTML 表格
function convertTables(md) {
  const lines = md.split('\n');
  const out = [];
  let i = 0;

  while (i < lines.length) {
    const line = lines[i];
    const isTableRow = l => /^\s*\|.*\|\s*$/.test(l);
    if (isTableRow(line) && i + 1 < lines.length && /^\s*\|?\s*:?-+:?\s*(\|\s*:?-+:?\s*)+\|?\s*$/.test(lines[i + 1])) {
      const tableLines = [];
      tableLines.push(line);
      tableLines.push(lines[i + 1]);
      i += 2;
      while (i < lines.length && isTableRow(lines[i])) {
        tableLines.push(lines[i]);
        i++;
      }

      const rows = tableLines.map(l =>
        l.trim().replace(/^\||\|$/g, '').split('|').map(c => c.trim())
      );
      const header = rows[0];
      const body = rows.slice(2);

      const thead = '<thead><tr>' + header.map(h => `<th>${h}</th>`).join('') + '</tr></thead>';
      const tbody = '<tbody>' + body.map(r => '<tr>' + r.map(c => `<td>${c}</td>`).join('') + '</tr>').join('') + '</tbody>';
      out.push('<table>' + thead + tbody + '</table>');
      continue;
    }
    out.push(line);
    i++;
  }

  return out.join('\n');
}

// Markdown转HTML
function markdownToHtml(md) {
  if (!md) return '';
  let html = convertTables(md);

  html = html.replace(/^###### (.*$)/gim, '<h6>$1</h6>');
  html = html.replace(/^##### (.*$)/gim, '<h5>$1</h5>');
  html = html.replace(/^#### (.*$)/gim, '<h4>$1</h4>');
  html = html.replace(/^### (.*$)/gim, '<h3>$1</h3>');
  html = html.replace(/^## (.*$)/gim, '<h2>$1</h2>');
  html = html.replace(/^# (.*$)/gim, '<h1>$1</h1>');
  html = html.replace(/\*\*(.*?)\*\*/g, '<strong>$1</strong>');
  html = html.replace(/\*(.*?)\*/g, '<em>$1</em>');
  html = html.replace(/`([^`]+)`/g, '<code>$1</code>');
  html = html.replace(/\[([^\]]+)\]\(([^)]+)\)/g, '<a href="$2">$1</a>');
  html = html.replace(/^---$/gim, '<hr/>');
  html = html.replace(/^[\*\-] (.+)$/gim, '<li>$1</li>');
  html = html.replace(/^(\d+)\. (.+)$/gim, '<li>$2</li>');
  html = html.replace(/(<li>.*<\/li>\n?)+/g, m => '<ul>' + m + '</ul>');

  const lines = html.split('\n');
  const result = [];
  let currentParagraph = [];

  for (const rawLine of lines) {
    const line = rawLine.trim();
    const isBlock = /^<table|^<\/table|^<thead|^<tbody|^<tr|^<th|^<td|^<h[1-6]|^<ul|^<\/ul|^<li|^<\/li|^<hr|^<strong|^<em|^<code|^<a/.test(line);
    if (isBlock) {
      if (currentParagraph.length) {
        result.push('<p>' + currentParagraph.join(' ') + '</p>');
        currentParagraph = [];
      }
      result.push(line);
      continue;
    }
    if (line === '') {
      if (currentParagraph.length) {
        result.push('<p>' + currentParagraph.join(' ') + '</p>');
        currentParagraph = [];
      }
      continue;
    }
    currentParagraph.push(line);
  }
  if (currentParagraph.length) {
    result.push('<p>' + currentParagraph.join(' ') + '</p>');
  }

  html = result.join('\n');
  html = html.replace(/<p>(<h[1-6]|<ul|<\/ul|<table)/g, '$1');
  html = html.replace(/(<\/h[1-6]>|<\/ul>|<\/table>)<\/p>/g, '$1');
  return html;
}

const cleaned = cleanEscapeChars(rawText);
const html = markdownToHtml(cleaned);

return {
  json: {
    profile: input.profile,
    calculations: input.calculations,
    assessment: {
      markdown: cleaned,
      html: html
    }
  }
};
```

## 2. 并行执行三个AI调用

### 问题
当前三个AI调用（评估、饮食、训练）是串行执行，总耗时 = 评估时间 + 饮食时间 + 训练时间。

### 解决方案
使用n8n的"Split In Batches"或"Merge"节点实现并行执行。

### 实施步骤

#### 步骤1：在"计算健康指标1"后添加Split节点
创建三个分支，分别准备三个AI调用的提示词。

#### 步骤2：并行执行三个AI调用
- 分支1：格式化评估提示词 → DeepSeek评估身体指标1
- 分支2：格式化饮食计划提示词 → DeepSeek生成饮食计划1  
- 分支3：格式化健身计划提示词 → DeepSeek生成健身计划1

#### 步骤3：使用Merge节点合并结果
在三个AI调用完成后，使用Merge节点合并结果，然后统一处理。

## 3. 增强错误处理和重试机制

### 问题
- AI调用失败时没有重试机制
- 文件保存失败时没有错误处理
- 邮件发送失败时没有通知

### 解决方案
为关键节点添加错误处理和重试逻辑。

### 实施步骤

#### 步骤1：为AI调用添加重试机制
在每个AI调用节点后添加错误处理节点：

```javascript
// AI调用错误处理和重试
const maxRetries = 3;
const retryDelay = 2000; // 2秒

async function callAIWithRetry(prompt, nodeName, retryCount = 0) {
  try {
    // 调用AI API
    const response = await $http.post('https://api.deepseek.com/v1/chat/completions', {
      model: 'deepseek-chat',
      messages: [
        { role: 'system', content: '...' },
        { role: 'user', content: prompt }
      ]
    });
    
    if (!response.choices || !response.choices[0]) {
      throw new Error('Invalid AI response');
    }
    
    return response.choices[0].message.content;
  } catch (error) {
    if (retryCount < maxRetries) {
      await new Promise(resolve => setTimeout(resolve, retryDelay * (retryCount + 1)));
      return callAIWithRetry(prompt, nodeName, retryCount + 1);
    }
    throw new Error(`${nodeName} failed after ${maxRetries} retries: ${error.message}`);
  }
}
```

#### 步骤2：为文件保存添加错误处理
在文件保存节点后添加错误处理：

```javascript
// 文件保存错误处理
try {
  // 保存文件逻辑
} catch (error) {
  return {
    json: {
      success: false,
      error: error.message,
      node: '文件保存',
      timestamp: new Date().toISOString()
    }
  };
}
```

#### 步骤3：为邮件发送添加错误处理
在邮件发送节点后添加错误处理节点，失败时记录日志并通知管理员。

## 4. 优化数据传递链路

### 问题
多处使用 `$('节点名').item.json` 跨节点获取数据，可读性差，容易出错。

### 解决方案
优化数据流，让数据通过节点链传递，减少跨节点引用。

### 实施步骤

#### 步骤1：在"计算健康指标1"后统一传递数据
创建一个"统一数据传递"节点，包含所有需要的数据：

```javascript
const data = $input.item.json;
return {
  json: {
    // 基础数据
    profile: data.profile,
    calculations: data.calculations,
    
    // 用于后续节点
    submissionId: data.submissionId || $('转换表单数据').first().json.submissionId,
    email: data.profile.email || $('转换表单数据').first().json.email
  }
};
```

#### 步骤2：修改所有后续节点
将所有 `$('节点名').item.json` 改为使用 `$json` 或上游节点传递的数据。

## 优化后的工作流结构

```
转换表单数据
  ↓
插入数据库
  ↓
提取数据
  ↓
数据验证
  ↓
计算健康指标
  ↓
统一数据传递 ← 新增
  ↓
Split (3个分支) ← 新增：并行执行
  ├─ 分支1: 格式化评估提示词 → AI评估 → 解析评估结果 → 清理转换评估
  ├─ 分支2: 格式化饮食提示词 → AI饮食 → 解析饮食计划 → 清理转换饮食
  └─ 分支3: 格式化训练提示词 → AI训练 → 解析训练计划 → 清理转换训练
  ↓
Merge ← 新增：合并结果
  ↓
组合所有结果
  ↓
准备保存数据
  ↓
保存文件（并行）
  ├─ JSON
  ├─ HTML
  └─ Markdown
  ↓
发送邮件
  ↓
更新数据库状态
```

## 预期效果

1. **代码重复减少**：从3个重复节点（约600行）减少到1个通用函数节点（约200行）+ 3个简单调用节点（各约10行）
2. **执行时间缩短**：三个AI调用从串行改为并行，预计节省约60-70%的时间
3. **错误处理增强**：所有关键节点都有错误处理和重试机制
4. **可维护性提升**：数据流清晰，减少跨节点引用

---

## 注意事项

1. 在n8n中，并行执行需要使用Split In Batches或Merge节点
2. 错误处理节点需要正确配置错误输出
3. 数据传递优化需要确保所有节点都能正确获取数据
4. 建议先在测试环境验证优化后的工作流
