### 一、平台覆盖与使用情况（告诉大家：平台“有多大、多广”）

- **1. DevOps 覆盖项目占比**
    - **故事点**：全公司多少项目已经接入 DevOps 平台。
    - **指标**：`已在 DevOps 平台中有流水线/代码库/需求记录的项目数 ÷ 公司全部在管项目数`。
    - **展示**：大号百分比 + 环形图。

- **2. DevOps 覆盖部门占比**
    - **故事点**：多少业务部门已经在用这套平台。
    - **指标**：`至少有一个项目/系统接入 DevOps 的部门数 ÷ 全部部门数`（基于 `sys_organization` + 项目/系统归属）。
    - **展示**：百分比 + 简单部门分布热力图（不点名也可以做匿名分布）。

- **3. 平台年度活跃用户占公司用户占比**
    - **故事点**：有多少同事在用 DevOps（不仅是研发）。
    - **指标**：`年度内在 DevOps 有行为（提交、构建、部署、操作需求/文档等）的独立用户数 ÷ 全体在职账号数`。
    - **展示**：百分比 KPI + 按角色/岗位的占比饼图（如果能区分的话）。

- **4. DevOps 平台日常活跃度趋势（弱化绝对值）**
    - **故事点**：平台“每天都在忙”，是日常工作基础设施。
    - **指标**：按日/周统计 `有活跃事件的天数占比`（例如一年中有多少天存在构建或部署）。
    - **展示**：年度热力日历（有事件标为高亮），不必显示精确数量。

### 二、研发效能与交付（让大家感知“迭代快了、上线更稳了”）

- **5. 部署频率提升倍数（今年 vs 去年）**
    - **故事点**：同样时间内，变更上生产的节奏更快。
    - **指标**：`本年度平均每周成功部署次数 ÷ 去年平均每周成功部署次数`。
    - **展示**：倍数（如“×2.3”）+ 趋势折线（两条曲线：今年与去年）。

- **6. 平均交付周期缩短比例**
    - **故事点**：从“提出需求/特性”到“上线”的时间明显下降。
    - **技术口径（友好型）**：
        - 每个 `devops_feature`：`首次成功部署时间 - feature.create_time`，取今年与去年的平均值。
    - **指标**：`(去年平均 Lead Time - 今年平均 Lead Time) ÷ 去年平均 Lead Time`。
    - **展示**：显示“交付周期缩短约 XX%”，不展示具体天数也可以。

- **7. 自动化流水线覆盖率**
    - **故事点**：上线环节自动化程度提高。
    - **指标**：`有 Jenkins/流水线配置并在本年度有执行记录的系统/项目数 ÷ 有上线记录的系统/项目总数`。
    - **展示**：百分比 + 柱状图分业务线（可匿名）。

- **8. 一键部署/标准化发布占比**
    - **故事点**：越来越少手工操作，更多标准化、一键式流程。
    - **指标**：`通过标准化流水线完成的部署次数 ÷ 总部署次数`。
    - **展示**：堆叠柱状图（自动化 vs 非自动化占比）。

### 三、质量与代码健康（强调“有检查、有改进”，用比率讲故事）

- **9. 代码扫描接入覆盖率**
    - **故事点**：有多少代码仓库已经纳入质量扫描。
    - **指标**：`本年度至少有一次静态扫描的代码仓库数 ÷ 全部在用代码仓库数`。
    - **展示**：大号百分比 + 趋势折线（覆盖率按月变化）。

- **10. 质量红线通过率（静态扫描 Gate 通过率）**
    - **故事点**：绝大多数构建/发布已经通过质量门禁。
    - **指标**：`满足质量门禁条件的扫描/构建次数 ÷ 触发质量门禁的总次数`。
    - **展示**：年度整体通过率 + 按月份的通过率折线；不展示“多少问题”，只讲“通过率”。

- **11. 问题闭环率（质量问题处理率）**
    - **故事点**：不是只发现问题，而是能闭环。
    - **指标**：按问题生命周期统计 `状态为“已修复/已关闭”的问题数量 ÷ 本年度产生的问题数量`。
    - **展示**：百分比 KPI + 环比趋势；不展示总问题数。

- **12. 代码质量持续改善指数（示意型）**
    - **故事点**：整体质量在稳步向好。
    - **指标**：可以用“每千行扫描发现问题数的同比变化率”作为一个综合评分（比如用 0–100 归一化成指数）。
    - **展示**：单条走势曲线 + 简短文案：“代码质量指数较年初提升 XX 分”。

### 四、安全与依赖可信（强调“可控”“合规”，弱化绝对漏洞数）

- **13. 可信扫描覆盖应用占比**
    - **故事点**：有多少应用已经纳入三方依赖/安全扫描体系。
    - **指标**：`至少进行过一次可信扫描的应用数 ÷ 有上线记录的应用总数`。
    - **展示**：大号百分比 + 按业务类型的占比饼图。

- **14. 安全门禁通过率**
    - **故事点**：上线前的安全检查多数都是“绿灯”。
    - **指标**：`通过安全门禁的构建/部署次数 ÷ 触发安全门禁的总次数`。
    - **展示**：百分比 KPI + 按月折线。

- **15. 高危问题处理率（不展示绝对数量）**
    - **故事点**：发现的高危问题都能快速处理。
    - **指标**：`本年度已关闭的高危安全/依赖风险数量 ÷ 本年度发现的高危风险数量`。
    - **展示**：百分比 + 处理时长分布（例如“80% 在 7 天内处理完”）。

### 五、知识与协同（科普平台“不是只管代码，还管知识”）

- **16. DevOps 知识空间接入项目占比**
    - **故事点**：多少项目已经有自己的知识空间/文档区。
    - **指标**：`在 DevOps 项目中有绑定 knowledge_space 的项目数 ÷ DevOps 总项目数`。
    - **展示**：百分比 + 条形图（按项目类型/业务线拆）。

- **17. 项目文档完备度**
    - **故事点**：项目有 README、设计说明、接口文档等标准材料。
    - **技术口径（友好型）**：基于 `knowledge_document` + `knowledge_template`，按“是否存在特定模版文档”计算。
    - **指标**：`满足至少 N 类关键文档（如 README + 架构说明 + 接口文档）的项目数 ÷ 有知识空间的项目数`。
    - **展示**：完备度百分比 + 雷达图展示“各类文档覆盖率”。

- **18. 知识参与度（评论/收藏参与率）**
    - **故事点**：不仅有文档，还有互动。
    - **指标**：`有评论/收藏记录的文档数 ÷ 全部文档数`，或 `参与评论/收藏的独立用户数 ÷ DevOps 活跃用户数`。
    - **展示**：百分比 + 简单趋势图。

### 六、规范执行与工程实践（传递“有规范、有落地”）

- **19. 提交规范检查覆盖率**
    - **故事点**：有多少仓库/项目启用了提交规范、MR 规范等自动检查。
    - **指标**：`配置了 commit/MR 规范检查规则并在本年度生效的项目数 ÷ 有代码仓库的项目数`（基于 `devops_commit_check_rule`、`devops_merge_request_setting`）。
    - **展示**：覆盖率百分比。

- **20. MR 审查通过率**
    - **故事点**：代码合入前，绝大多数都经过合规审查。
    - **指标**：`正常合并完成的 MR 数量 ÷ 提交的 MR 总数`。
    - **展示**：通过率 + 小趋势图；不展示绝对 MR 数。

- **21. 标准流水线模板使用率**
    - **故事点**：团队在复用平台提供的最佳实践，而不是各自为政。
    - **指标**：`基于平台标准模板创建的流水线运行次数 ÷ 全部流水线运行次数`。
    - **展示**：百分比 KPI + 饼图（标准模板 vs 自定义）。
