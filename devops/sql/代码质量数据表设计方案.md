# 代码质量数据表设计方案

## 一、现有表结构分析

### 1.1 核心表关系

```
code_repository (代码仓库表)
    ↓ scan_task_id
scan_task (扫描任务表)
    ↓ id
scan_history (扫描历史表) ← 核心质量数据表
    ↓ id
scan_issue (扫描问题表) ← 详细问题数据
```

### 1.2 关键字段分析

#### scan_history 表（扫描历史表）
- **质量指标字段**：
  - `score` - 平台打分分值
  - `bug` - bug数量
  - `code_smell` - 代码异味数量
  - `vulnerability` - 漏洞数量
  - `coverage` - 代码覆盖率
  - `repetition` - 代码重复率
  - `result` - 质量门禁状态（0-未通过，1-通过）
- **关联字段**：
  - `scan_task_id` - 关联扫描任务
  - `repository_url` - 代码仓库地址（冗余字段）
  - `branch` - 仓库分支
  - `quality_gate_id` - 质量门禁ID
  - `scan_plan_id` - 扫描方案ID
- **租户字段**：`tenant_id`

#### scan_issue 表（扫描问题表）
- **问题分类**：
  - `issue_type` - 问题类型（BUG, VULNERABILITY, CODE_SMELL）
  - `severity` - 严重程度（BLOCKER, CRITICAL, MAJOR, MINOR）
- **关联字段**：
  - `history_id` - 关联扫描历史
- **租户字段**：`tenant_id`

#### scan_task 表（扫描任务表）
- **关键字段**：
  - `project_key` - 项目key（唯一标识）
  - `language` - 扫描语言
- **租户字段**：`tenant_id`

#### code_repository 表（代码仓库表）
- **关键字段**：
  - `id` - 仓库ID
  - `repository_url` - 仓库地址
  - `branch` - 分支
  - `scan_task_id` - 关联扫描任务
- **租户字段**：`tenant_id`

### 1.3 数据流向

```
代码仓库 → 扫描任务 → 扫描历史 → 扫描问题
(code_repository) → (scan_task) → (scan_history) → (scan_issue)
```

## 二、设计目标

基于现有表结构，设计一套代码质量数据表，用于：
1. **按代码仓库维度**统计质量数据（一个仓库对应一个扫描任务）
2. **按时间维度**记录历史质量数据
3. **按统计维度**生成趋势数据（按天/周/月）
4. **支持多租户**数据隔离

## 三、表结构设计

### 3.1 代码仓库质量统计表（code_repository_quality）

**用途**：存储每个代码仓库的最新质量指标数据，按仓库维度统计。

**设计思路**：
- 一个 `code_repository.id` 对应一条记录
- 从 `scan_history` 表获取最新扫描记录的质量数据
- 从 `scan_issue` 表统计问题数量（按严重程度和类型）

**表名**：`code_repository_quality`

**字段设计**：

| 字段名 | 类型 | 说明 | 数据来源 |
|--------|------|------|----------|
| id | bigint | 主键，自增 | - |
| repository_id | bigint | 代码仓库ID | code_repository.id |
| repository_url | varchar(500) | 代码仓库地址 | scan_history.repository_url |
| branch | varchar(100) | 仓库分支 | scan_history.branch |
| project_key | varchar(64) | 项目key | scan_task.project_key |
| scan_task_id | bigint | 扫描任务ID | scan_task.id |
| latest_scan_history_id | bigint | 最新扫描历史ID | scan_history.id (MAX(scan_time)) |
| latest_scan_time | datetime | 最新扫描时间 | scan_history.scan_time |
| quality_score | decimal(10,2) | 质量评分 | scan_history.score |
| bug_count | int | Bug数量 | scan_history.bug 或 scan_issue统计 |
| vulnerability_count | int | 漏洞数量 | scan_history.vulnerability 或 scan_issue统计 |
| code_smell_count | int | 代码异味数量 | scan_history.code_smell 或 scan_issue统计 |
| blocker_count | int | 致命问题数量 | scan_issue统计 (severity='BLOCKER') |
| critical_count | int | 严重问题数量 | scan_issue统计 (severity='CRITICAL') |
| major_count | int | 主要问题数量 | scan_issue统计 (severity='MAJOR') |
| minor_count | int | 次要问题数量 | scan_issue统计 (severity='MINOR') |
| coverage | decimal(10,2) | 代码覆盖率 | scan_history.coverage |
| duplication | decimal(10,2) | 代码重复率 | scan_history.repetition |
| quality_gate_status | tinyint | 质量门禁状态 | scan_history.result |
| quality_gate_id | bigint | 质量门禁ID | scan_history.quality_gate_id |
| scan_plan_id | bigint | 扫描方案ID | scan_history.scan_plan_id |
| language | varchar(64) | 主要编程语言 | scan_task.language |
| creator | varchar(64) | 创建者 | - |
| create_time | datetime | 创建时间 | - |
| updater | varchar(64) | 更新者 | - |
| update_time | datetime | 更新时间 | - |
| deleted | bit(1) | 是否删除 | - |
| tenant_id | bigint | 租户编号 | scan_history.tenant_id |

**索引设计**：
- PRIMARY KEY (`id`)
- UNIQUE KEY `uk_repository_tenant` (`repository_id`, `tenant_id`) - 确保一个租户下一个仓库只有一条记录
- INDEX `idx_repository_id` (`repository_id`)
- INDEX `idx_project_key` (`project_key`)
- INDEX `idx_tenant_id` (`tenant_id`)
- INDEX `idx_latest_scan_time` (`latest_scan_time`)
- INDEX `idx_quality_score` (`quality_score`)

- 从 `scan_issue` 表统计问题数量

| scan_task_id | bigint | 扫描任务ID | scan_history.scan_task_id |
| scan_history_id | bigint | 扫描历史ID | scan_history.id |
| scan_time | datetime | 扫描时间 | scan_history.scan_time |
| quality_score | decimal(10,2) | 质量评分 | scan_history.score |
| bug_count | int | Bug数量 | scan_history.bug |
| vulnerability_count | int | 漏洞数量 | scan_history.vulnerability |
| code_smell_count | int | 代码异味数量 | scan_history.code_smell |
| blocker_count | int | 致命问题数量 | scan_issue统计 |
| critical_count | int | 严重问题数量 | scan_issue统计 |
| major_count | int | 主要问题数量 | scan_issue统计 |
| minor_count | int | 次要问题数量 | scan_issue统计 |
| coverage | decimal(10,2) | 代码覆盖率 | scan_history.coverage |
| duplication | decimal(10,2) | 代码重复率 | scan_history.repetition |
| quality_gate_status | tinyint | 质量门禁状态 | scan_history.result |
| quality_gate_id | bigint | 质量门禁ID | scan_history.quality_gate_id |
| scan_plan_id | bigint | 扫描方案ID | scan_history.scan_plan_id |

| build_id | bigint | 构建ID | scan_history.build_id |
| creator | varchar(64) | 创建者 | scan_history.create_by |
| create_time | datetime | 创建时间 | scan_history.create_time |
| updater | varchar(64) | 更新者 | scan_history.update_by |

### 3.3 代码仓库质量趋势表（code_repository_quality_trend）

**用途**：存储每个代码仓库的质量趋势数据，按天/周/月维度统计，用于趋势分析。

**设计思路**：
- 基于 `code_repository_quality_history` 表聚合统计
- 按天/周/月三个维度分别统计
- 计算平均值、最大值、最小值等统计指标

**表名**：`code_repository_quality_trend`

**字段设计**：

| 字段名 | 类型 | 说明 | 计算方式 |
|--------|------|------|----------|
| id | bigint | 主键，自增 | - |
| repository_id | bigint | 代码仓库ID | - |
| repository_url | varchar(500) | 代码仓库地址 | - |
| project_key | varchar(64) | 项目key | - |
| stat_date | date | 统计日期 | 按天：DATE(scan_time)<br>按周：周一的日期<br>按月：每月1号 |
| stat_type | tinyint | 统计类型 | 0-按天，1-按周，2-按月 |
| scan_count | int | 扫描次数 | COUNT(*) |
| avg_quality_score | decimal(10,2) | 平均质量评分 | AVG(quality_score) |
| max_quality_score | decimal(10,2) | 最高质量评分 | MAX(quality_score) |
| min_quality_score | decimal(10,2) | 最低质量评分 | MIN(quality_score) |
| total_bug_count | int | 累计Bug数量 | SUM(bug_count) |
| total_vulnerability_count | int | 累计漏洞数量 | SUM(vulnerability_count) |
| total_code_smell_count | int | 累计代码异味数量 | SUM(code_smell_count) |
| avg_coverage | decimal(10,2) | 平均代码覆盖率 | AVG(coverage) |
| avg_duplication | decimal(10,2) | 平均代码重复率 | AVG(duplication) |
| quality_gate_pass_rate | decimal(10,2) | 质量门禁通过率 | COUNT(quality_gate_status=1) / COUNT(*) * 100 |
| quality_improvement | decimal(10,2) | 质量改善度 | (本期avg_quality_score - 上期avg_quality_score) |
| creator | varchar(64) | 创建者 | - |
| create_time | datetime | 创建时间 | - |
| updater | varchar(64) | 更新者 | - |
| update_time | datetime | 更新时间 | - |
| deleted | bit(1) | 是否删除 | - |
| tenant_id | bigint | 租户编号 | - |

**索引设计**：
- PRIMARY KEY (`id`)
- UNIQUE KEY `uk_repository_stat` (`repository_id`, `stat_date`, `stat_type`, `tenant_id`) - 确保一个租户下一个仓库一个统计周期只有一条记录
- INDEX `idx_repository_id` (`repository_id`)
- INDEX `idx_project_key` (`project_key`)
- INDEX `idx_tenant_id` (`tenant_id`)
- INDEX `idx_stat_date` (`stat_date`)
- INDEX `idx_stat_type` (`stat_type`)
- INDEX `idx_repository_stat_date` (`repository_id`, `stat_date`, `stat_type`) - 用于查询趋势

## 四、数据同步策略

### 4.1 数据来源映射

| 目标表 | 数据来源 | 同步时机 |
|--------|----------|----------|
| code_repository_quality | scan_history (最新记录) + scan_issue (统计) | 每次扫描完成后 |
| code_repository_quality_history | scan_history + scan_issue (统计) | 每次扫描完成后 |
| code_repository_quality_trend | code_repository_quality_history (聚合) | 定时任务（每天凌晨） |

### 4.2 数据计算逻辑

#### 问题数量统计（从 scan_issue 表）
```sql
-- 统计某个扫描历史的问题数量
SELECT 
    COUNT(CASE WHEN issue_type = 'BUG' AND del_flag = 0 AND ignore_flag = 0 THEN 1 END) AS bug_count,
    COUNT(CASE WHEN issue_type = 'VULNERABILITY' AND del_flag = 0 AND ignore_flag = 0 THEN 1 END) AS vulnerability_count,
    COUNT(CASE WHEN issue_type = 'CODE_SMELL' AND del_flag = 0 AND ignore_flag = 0 THEN 1 END) AS code_smell_count,
    COUNT(CASE WHEN severity = 'BLOCKER' AND del_flag = 0 AND ignore_flag = 0 THEN 1 END) AS blocker_count,
    COUNT(CASE WHEN severity = 'CRITICAL' AND del_flag = 0 AND ignore_flag = 0 THEN 1 END) AS critical_count,
    COUNT(CASE WHEN severity = 'MAJOR' AND del_flag = 0 AND ignore_flag = 0 THEN 1 END) AS major_count,
    COUNT(CASE WHEN severity = 'MINOR' AND del_flag = 0 AND ignore_flag = 0 THEN 1 END) AS minor_count
FROM scan_issue
WHERE history_id = ?
```

#### 最新扫描记录获取
```sql
-- 获取每个扫描任务的最新扫描记录
SELECT sh.*
FROM scan_history sh
INNER JOIN (
    SELECT scan_task_id, MAX(scan_time) AS max_scan_time
    FROM scan_history
    WHERE del_flag = 0
    GROUP BY scan_task_id
) latest ON sh.scan_task_id = latest.scan_task_id 
    AND sh.scan_time = latest.max_scan_time
WHERE sh.del_flag = 0
```

## 五、查询场景示例

### 5.1 查询租户下所有代码仓库的最新质量数据
```sql
SELECT 
    rq.*,
    cr.repository_url,
    cr.branch
FROM code_repository_quality rq
LEFT JOIN code_repository cr ON rq.repository_id = cr.id
WHERE rq.tenant_id = ? 
  AND rq.deleted = 0
ORDER BY rq.latest_scan_time DESC
```

### 5.2 查询指定代码仓库的质量历史趋势（最近30条）
```sql
SELECT 
    scan_time,
    quality_score,
    bug_count,
    vulnerability_count,
    code_smell_count,
    coverage,
    duplication
FROM code_repository_quality_history
WHERE repository_id = ?
  AND tenant_id = ?
  AND deleted = 0
ORDER BY scan_time DESC
LIMIT 30
```

### 5.3 查询代码仓库质量趋势（按月，最近12个月）
```sql
SELECT 
    stat_date,
    avg_quality_score,
    total_bug_count,
    total_vulnerability_count,
    quality_gate_pass_rate
FROM code_repository_quality_trend
WHERE repository_id = ?
  AND stat_type = 2  -- 按月
  AND tenant_id = ?
  AND deleted = 0
ORDER BY stat_date DESC
LIMIT 12
```

### 5.4 查询租户下质量评分低于阈值的代码仓库
```sql
SELECT 
    rq.*,
    cr.repository_url
FROM code_repository_quality rq
LEFT JOIN code_repository cr ON rq.repository_id = cr.id
WHERE rq.tenant_id = ?
  AND rq.quality_score < 60  -- 质量评分低于60分
  AND rq.deleted = 0
ORDER BY rq.quality_score ASC
```

## 六、注意事项

1. **租户隔离**：所有查询必须包含 `tenant_id` 条件，确保数据隔离
2. **数据一致性**：`code_repository_quality` 表的数据应与 `scan_history` 表的最新记录保持一致
3. **性能优化**：对于历史数据查询，建议使用分页查询，避免一次性查询大量数据
4. **数据清理**：建议定期清理 `code_repository_quality_history` 表中的过期数据（如保留最近1年的数据）
5. **索引维护**：定期检查索引使用情况，根据实际查询场景优化索引
6. **唯一性约束**：使用唯一索引确保数据不重复，避免重复同步
