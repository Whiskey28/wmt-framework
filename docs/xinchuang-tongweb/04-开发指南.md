# 开发指南（业务侧）

## 1. 推荐分层

- `controller`：只处理入参与出参，不写业务细节
- `service`：业务编排、事务边界
- `mapper`：数据访问
- `convert`：DTO 与 DO 转换

## 2. 接口开发流程

1. 定义入参 DTO 并添加校验注解
2. Controller 调用 Service
3. Service 内完成事务与业务校验
4. 返回统一响应模型
5. 为核心接口补充单元测试

## 3. 鉴权开发建议

- 对外接口显式标记权限点
- 对高风险操作记录操作日志
- 当前登录用户信息统一从安全上下文读取

## 4. 多租户开发建议

- 所有核心表保留租户标识
- 跨租户操作必须通过白名单能力
- 异步任务与消息消费场景要传递租户上下文

## 5. WebSocket 与消息开发建议

- 优先定义统一消息体（类型、业务键、时间戳）
- 集群场景使用 `mq + websocket` 组合实现广播
- 对客户端断线重连与幂等消费做好兜底
