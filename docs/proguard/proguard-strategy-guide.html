ProGuard 策略
业务方无感，逆向更难。

你们发布的是混淆后的 JAR，不是源码。业务方通过 Maven 依赖的方式使用组件库， 写代码、调 API、配 Spring Boot 的体验与明文版本基本一致—— 变化主要发生在 JAR 内部和反编译可读性上。

业务方看到的是什么？

从依赖坐标到 IDE 自动补全，绝大多数层面「看起来没变」。

1

pom.xml 依赖

groupId / artifactId / version 完全不变，仍是 com.wmt 坐标

2

IDE 自动补全

CommonResult、PageParam、@Valid 等类名方法名照常提示

3

Spring Boot 启动

AutoConfiguration.imports 中的类名未变，自动配置正常加载

4

运行时行为

Controller 仍 return CommonResult；全局异常仍转统一 JSON

🛡️

保运行

-dontshrink -dontoptimize：不删类、不做激进优化，避免 Spring / MyBatis / Jackson 反射失败。

📦

保对外 API

CommonResult、PageParam、common.biz 接口、@ConfigurationProperties 字段名等稳定不变。

🔒

混淆内部

private 字段、lambda、package-info 可缩短；剥离 SourceFile / LineNumberTable。

Before → After 对比

左侧是仓库里的原始形态；右侧是业务方拿到混淆 JAR 后「能看到 / 能用到」的形态。

1

Maven 依赖坐标

完全一致

业务方 pom.xml 无需任何改动，换的是 JAR 内容，不是坐标。

发布前 / 发布后 · 相同
<dependency> <groupId>com.wmt</groupId> <artifactId>wmt-spring-boot-starter-web</artifactId> <version>2025.12-jdk17-SNAPSHOT</version> </dependency> // IDE 仍解析到同一套 com.wmt.framework.* 包名
业务方感知
✓ 不需要改依赖 ✓ 不需要改 import ✓ 不需要改 application.yml 里 wmt.* 配置项名称 // 唯一区别：本地 ~/.m2 里存的是混淆后字节码 // 而非你们 Git 仓库里的 .java 源文件
2

Controller 返回 CommonResult

API 保留

common.pojo.** 完整 keep，业务方写法和编译期类型检查不变。

业务方 Controller 源码
@GetMapping("/get") public CommonResult<FooVO> getFoo(@RequestParam Long id) { FooVO vo = fooService.getFoo(id); return CommonResult.success(vo); } // CommonResult 类在 wmt-common JAR 里 // 字段 code / msg / data 名称保留
混淆 JAR 中 javap 可见
public class com.wmt.framework.common.pojo.CommonResult { public static CommonResult success(Object data); public static CommonResult error(Integer code, String msg); public Integer getCode(); public String getMsg(); public Object getData(); public boolean isSuccess(); } // 与明文 JAR 签名一致
✓ 业务方代码零改动；JSON 响应结构不变
3

分页 PageUtils / PageParam

public 方法保留

util.** 只 keep public 成员；private 与 lambda 在 wmt-common 内被混淆。

仓库源码 PageUtils.java
public class PageUtils { public static int getStart(PageParam param) { ... } private static Integer CACHE_MAX_SIZE = 1000; // private 字段、lambda 辅助方法... }
混淆后 · 业务方仍这样写
// 业务 Mapper / Service PageResult<FooDO> page = fooMapper.selectPage( pageParam, new QueryWrapper<>() ); // IDE 仍提示： PageUtils.getStart(pageParam) ✓ PageParam.getPageNo() ✓ // proguard_map 内部映射（不随 JAR 发布）： CACHE_MAX_SIZE → a lambda$convertMap$3 → b

GlobalExceptionHandler

类名 + 公共方法保留

core.** 整体 keep 类名；元数据剥离后反编译看不到源文件与行号。

仓库源码 + 编译 class
// GlobalExceptionHandler.java @RestControllerAdvice public class GlobalExceptionHandler { private ApiErrorLogCommonApi apiErrorLogApi; @ExceptionHandler(ServiceException.class) public CommonResult<?> serviceExceptionHandler(...) { } private void createExceptionLog(...) { } } javap -verbose 编译产物： Compiled from "GlobalExceptionHandler.java" SourceFile: "GlobalExceptionHandler.java" LineNumberTable: ...
混淆 JAR · 业务运行时
// 业务抛 ServiceException → 仍得到 CommonResult JSON { "code": 400, "msg": "xxx", "data": null } // javap 混淆 JAR： public class ...GlobalExceptionHandler { ✓ 类名不变 public CommonResult serviceExceptionHandler(...) ✓ } 无 SourceFile / LineNumberTable / Compiled from // 用 jadx 打开 JAR：无法定位到 .java 文件名与行号

MyBatis Mapper 接口

接口全保留

业务方自己的 Mapper 不受影响；框架内 Mapper 接口名保留。

业务方代码
@Mapper public interface FooMapper extends BaseMapperX<FooDO> { // 业务自定义 SQL } // 框架提供 BaseMapperX.selectPage(pageParam, wrapper)
混淆后
✓ BaseMapperX 公共方法签名保留 ✓ @Mapper 接口 keep 规则生效 ✓ TypeHandler / MetaObjectHandler 实现类名保留 // 分页、联表 MPJ 照常工作

校验注解 @Mobile / @InEnum

Validator 保留

Hibernate Validator 按类名实例化 ConstraintValidator，相关类完整 keep。

业务 DTO
public class UserCreateReqDTO { @Mobile private String mobile; @InEnum(UserTypeEnum.class) private Integer userType; }
混淆后校验行为
✓ @Mobile 仍触发 MobileValidator ✓ 校验失败仍走 GlobalExceptionHandler ✓ 返回 CommonResult code=400 // validation.** 与 @Constraint 类名均未混淆

Jackson 时间戳序列化

Serializer 类名保留

自定义 Serializer 在配置类中按 Class 注册，类名不能变。

框架注册方式

混淆 JAR
...TimestampLocalDateTimeSerializer 类名不变 ...TimestampLocalDateTimeDeserializer 类名不变 // 业务 JSON 中 LocalDateTime 仍输出时间戳 { "createTime": 1716537600000 }

你们如何构建

业务方只消费 Maven 仓库里的 JAR，构建发生在 wmt-framework 仓库内。

发布命令

# 默认混淆（当前策略，含元数据剥离）
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PROGUARD_JDK_HOME="$JAVA_HOME"
mvn -f wmt-framework-jdk17/pom.xml clean package -Pobfuscate -DskipTests

# 加强版（独立规则链，预留后续收紧 keep）
mvn -f wmt-framework-jdk17/pom.xml clean package -Pobfuscate-strong -DskipTests

# 规则文件
docs/proguard/proguard-jdk17-library.conf   # wmt-common
docs/proguard/proguard-jdk17-starter.conf   # 16 个 starter
